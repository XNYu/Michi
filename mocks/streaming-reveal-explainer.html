Streaming 渐入方案
现在是怎么做的

目标是让新出现的字从淡到深，同时避免旧字反复动画、React 节点来回替换、code block 灰块闪现。

当前参数
duration: 300ms
from opacity: 0.28
结束 streaming 后回到普通 Markdown

一眼看懂

01
后端 chunk

后端持续追加文本，前端收到的是累计答案。

02
useSmooth

把 bursty chunk 平滑释放成可见文本。

03
streamingProjection

只负责告诉 MarkdownContent：这个 segment 正在 streaming。

04
MarkdownContent

比较上一帧可见文本，只标记真正新增的字符。

05
CSS 动画

旧字符 duration 为 0ms，新字符 duration 为 300ms。

方案地图

核心思想

不再猜“尾部 80 字”

以前只能猜最后一段大概是新内容，所以旧字也会反复动画。现在记录上一帧可见文本，精确知道哪些字是新增的。

DOM 形态稳定

streaming 期间，普通正文字符始终渲染成 span。旧字和新字节点类型一致，只是动画时长不同。

Code block 跳过

代码块有背景和布局，不适合文字渐入。当前方案遇到 block code 会关闭 reveal，并压掉空 code shell。

时间线

假设第一帧显示 “hello”，第二帧变成 “hello 世界”。只有 “世界” 是新增字符。

Frame A
commit 后记录
h e l l o
Frame B
render 时比较
h e l l o 空格 世 界
Frame B
CSS 结果
旧字: 0ms 新增: 300ms
已经出现过的字符，保留 span，但不动画 本帧新增字符，执行 300ms 渐入

DOM 对比

会闪的方向

旧字一会儿是 span，一会儿又变成普通 text node，React diff 时容易闪。

Frame A <span class="stream-token-reveal">h</span> <span class="stream-token-reveal">e</span> Frame B hello <span class="stream-token-reveal">世</span>

现在的方向

旧字和新字都保持 span，区别只在 CSS duration。

Frame B <span class="stream-token-reveal" style="--stream-token-reveal-duration:0ms">h</span> <span class="stream-token-reveal" data-stream-token-new>世</span>

React / StrictMode 为什么要注意

不要在 render 过程中写 previousText

React dev mode 可能重复 render。若第一次 render 就把 previousText 写成当前文本，第二次 render 会误判“没有新增字”，渐入效果就消失。

现在在 commit 后记录

用 useLayoutEffect 从真实 DOM 读取可见文本。只有 DOM 确实更新后，才把它作为下一帧的 previousText。

useLayoutEffect(() => {
  previousText = revealEnabled && rootRef.current
    ? domRevealText(rootRef.current)
    : "";
}, [text, revealEnabled]);

Code block 特殊处理

为什么跳过

代码块不是普通正文。它有灰色背景、padding、pre/code 结构。若继续渐入，用户会看到一整块灰色容器先出现，再慢慢填实，很奇怪。

现在怎么做

如果 HAST 里出现 <pre>，整段 reveal 插件直接退出。若只是空代码块 shell，也先删除这个空 <pre>。

if (hasBlockCode(tree)) {
  return;
}

if (pre is empty) {
  drop it;
}

当前方案的取舍

稳定性

比“span 和 text node 来回切换”稳定。旧内容不会重复动画，DOM 类型也更一致。

性能

streaming 期间会多一些 span 节点。结束后 reveal 关闭，重新回到普通 Markdown，历史消息不会一直带这些 span。

边界

Markdown 结构大幅重排时仍可能有局部跳动，比如列表、表格、代码块识别状态变化。这是 streaming Markdown 的固有难点。

一句话总结： 我们现在不是靠“最后一段字”猜动画范围，而是用上一帧真实可见文本来判断新增字符；同时保持 streaming 期间 DOM 节点形态稳定，用 CSS duration 控制旧字不动画、新字渐入。
